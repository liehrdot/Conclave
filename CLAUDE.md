# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The app is called **Conclave** (renamed from "MTG Deckbuilder" after 0.1.9). Only the name people see changed: the Tauri identifier `app.mtgdeck.desktop`, the data folder `%APPDATA%\MTG Deckbuilder` (`paths.DATA_FOLDER`, `backend::APP_FOLDER`), the package/command names (`mtgdeck`, `mtg-gui`) and the repo name stay, so installs keep updating and keep their data. `hooks.nsh` removes an old "MTG Deckbuilder" install after the first Conclave install. Since 0.2.1 the programs are `Conclave.exe` (`mainBinaryName`; the Cargo package stays `mtgdeck-desktop`) and `conclave-backend.exe`. "Am Tisch" is now only the phone's table tab.

A Magic: The Gathering Commander (EDH) deckbuilder without AI: the user builds decks themself (empty deck + editor, or import by link, list or precon), and the app looks cards up, checks rules and brackets, saves versions, play-tests, prints proxies and syncs between PC and phone. There is a web GUI (FastAPI + vanilla JS), a Windows desktop shell (Tauri) around it, a sync server and a phone PWA.

The app has no Claude features any more (removed on purpose; the owner wants to build decks with their own thinking). Don't add AI features back unless asked. The only "KI" left is the optional local image upscaler (Real-ESRGAN) for proxy prints, plus one scoped exception the owner asked for on 2026-10-13: the phone's card search by description (`sync/cardsearch.py`, Claude via the owner's API key only translates a description into Scryfall syntax; no deck advice). Old AI outputs in user data (`decks/.chats/`, `deck["guide"]`, `deck["upgrade_plan"]`, `built_against`) are kept and still sync, but nothing shows them. Answer in English unless the user writes in another language; the app UI is German.

## Commands

```bash
uv sync --all-extras                               # install (extras: gui, dev)
uv run pytest                                      # all tests (offline, <2 s)
uv run pytest tests/test_validate.py::test_game_changer_limits   # single test
uv run mtg-gui                                     # web GUI on http://127.0.0.1:8765 (mtgdeck.launch: --data DIR --port 0 --token auto)
uv run pyinstaller desktop/sidecar/backend.spec     # desktop backend as a folder build → dist/conclave-backend/ (extra: desktop)
cargo check --manifest-path desktop/src-tauri/Cargo.toml --target x86_64-pc-windows-msvc   # the Tauri shell compiles (the Windows build itself runs in CI)
uv run python scripts/bump_version.py 0.2.0           # version in pyproject, gui/app.py, Cargo.toml/.lock, tauri.conf.json; then tag v0.2.0 → release workflow
uv run mtg-sync-server                             # sync server on :8080 (normally the Docker image, deploy/sync)
```

No linter or formatter is configured. Code uses `# fmt: skip` on some dense literals, so black/ruff-format style is expected.

## Architecture

**Layers in `src/mtgdeck/`:**
- **`paths.py`** (no package imports): the roots every module reads its default path from. `home()` = user data (`MTG_HOME`, else the repo root in a checkout, else the platform app-data folder `%APPDATA%\MTG Deckbuilder` (`DATA_FOLDER`, the old name on purpose) when `frozen()` = packaged with PyInstaller), `cache_home()` = card DB + HTTP cache (`MTG_CACHE_HOME`). The per-file env vars (`MTG_DECKS_DIR` …) still win.
- **`launch.py`**: the `mtg-gui` entry point and the packaged backend's. Arguments (`--data`, `--cache`, `--host`, `--port` (0 = a free port), `--token TOKEN|auto`) become env vars *before* the app modules import. `gui.serve()` binds the socket itself and prints one line `MTGDECK_URL=http://127.0.0.1:<port>/?token=…` for the desktop shell. With `GUI_TOKEN` set, the `_guard` middleware requires it on everything but `_OPEN_PATHS` (`/api/health`, static): the first `/?token=` link sets the HttpOnly cookie `mtg_token` (SameSite=Lax, never Strict: the shell's start page is on tauri.localhost, and a Strict cookie is not sent on the navigation after the redirect) and redirects, `Authorization: Bearer` works too. `GET /api/health` = readiness (`ok`, `version`, `home`, `frozen`).
- **`desktop/`** (plan `docs/plan-desktop-app.md`): `sidecar/backend.spec` (PyInstaller `--onedir`: static files; excludes the sync server), `sidecar/entry.py`. `src-tauri/` is the Tauri 2 shell (Rust, Windows): `backend.rs` supervises `resources/backend/conclave-backend.exe` (`MTGDECK_BACKEND` env, else `dist/conclave-backend/` for `cargo tauri dev`; started with `--data %APPDATA%\MTG Deckbuilder --cache %LOCALAPPDATA%\app.mtgdeck.desktop\cache --port 0 --token auto` (the cache sits under the app identifier because a per-user NSIS install itself lives in `%LOCALAPPDATA%\Conclave`; `dirs()` moves a cache from the first versions over once), output → `<data>/logs/backend.log`, restarts with `BACKOFF` 1/2/5/5/5 s, a run longer than `HEALTHY_AFTER` resets the budget, then state `failed` with the log tail; events `backend-status` / `backend-ready`); `lib.rs` = single instance (registered first), the main window built in `setup` from its config entry (`create: false`) so `on_navigation` can send moxfield.com links to `moxfield.rs`, window state, autostart (`--hidden` = tray only), tray (Öffnen, Datenordner öffnen, „Beim Anmelden starten“, Beenden), closing hides the window with one notification, commands `backend_status` / `restart_backend` / `open_log`, `--selftest` (start the backend, GET `/api/health`, expect `ok` + `frozen`, exit code) for CI. `ui/index.html` is the local start page (skeleton, listens for the events, navigates to the backend URL; the web app itself runs on 127.0.0.1 and needs no IPC, so `security.csp: null` only covers this page and the capability lists only `core:default`, `window-state`, `notification`; Rust calls the autostart and updater plugins itself). `bridge.rs` long-polls `POST /api/desktop/poll` (Bearer token from the URL, `{since, visible, autostart, version, features, wait: 8}`; the backend holds it until a command or notice is queued, so a click reaches the shell at once; at most one poll a second, 10 s after a failure) and applies the answer: tray tooltip, notices as system notifications while the window is hidden, commands `autostart` (keeps the tray check item in step) / `open_data` / `open_log` / `check_update` / `install_update`. `updates.rs` (plugin `tauri-plugin-updater` with native TLS and without zip, so the Windows-target `cargo check` still works on Linux): `check()` 45 s after the start and daily against `plugins.updater.endpoints` (the GitHub release's `latest.json`, signature checked with `pubkey`), `install()` = `download`, then `backend::stop()` (`kill_tree`: `taskkill /T`, so child processes go too – their open files in `resources/backend` made the installer fail), then `Update::install` (NSIS passive, the app restarts; on failure the backend is started again). Which `latest.json` it checks comes from the backend (`GET /api/desktop/feed`, `gui/releases.py`): the stable `releases/latest/download/latest.json`, the newest preview build with setting `desktop_preview` („Vorschau-Versionen anzeigen“), or one picked version for command `install_version` (comparator „different“, so going back works; any other check only takes newer versions); the feed must start with this repo's releases URL. Preview builds: `.github/workflows/preview.yml` on every app change on master builds `<next patch>-preview.<run>` (only `tauri.conf.json` is changed in CI), publishes a prerelease with tag `preview-<version>` and `--latest=false` (GitHub never makes a prerelease the latest, so the stable feed cannot pick it up) and keeps the newest `KEEP`. `GET /api/desktop/releases` lists the installable versions (published, with `latest.json`; previews only with the setting on) for „Andere Version installieren“ in the settings panel (a backup is made first). `hooks.nsh` (`bundle.windows.nsis.installerHooks`) kills `conclave-backend.exe` (and the pre-0.2.1 `mtgdeck-backend.exe` / `mtgdeck-desktop.exe`) before the installer copies or removes files, so manual installs over a running app and updates from older versions work too; after installing it deletes the old exes, retargets a pinned taskbar icon and the autostart entry, and creates the Start menu entry once if missing (an `/UPDATE` install never creates one, so the in-app update from „MTG Deckbuilder“ left none and Windows Search found nothing); the state (`unknown|none|available|preparing|downloading|verifying|installing|error|unconfigured`, `rev` (≥ the time in ms, so it grows across restarts), version, notes, progress, `downloaded`/`total`/`speed` in bytes, error, `failed_step`, checked) rides in the poll body as `update`; while an install runs, `reporter()` also pushes every change to `POST /api/desktop/update` (every 250 ms) and `report()` once more right before the backend stops. A restarted backend has a new port: `backend::follow()` sends a main window still on the old address there (hash kept), e.g. after a failed install. `bundle.createUpdaterArtifacts: true` needs the signing key, so the push workflow builds with `--config tauri.nosign.conf.json`; the release workflow `.github/workflows/release.yml` (tag `v*`: the five version places must match, backend build + smoke, `tauri-apps/tauri-action` with secrets `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`) publishes installer, `.sig` and `latest.json`. `tauri.conf.json` bundles `../../dist/conclave-backend/` as `resources/backend/`, NSIS per user, WebView2 bootstrapper. Workflow `.github/workflows/desktop.yml` (Windows): backend build + smoke test (port 0, token, health, 401 without token, no Agent SDK bundled), `npx @tauri-apps/cli build`, `--selftest`, installer as artifact. `cargo check --target x86_64-pc-windows-msvc` works on Linux; a Linux Tauri build does not (no webkit2gtk).
- **`gui/desktop.py`**: the backend side of the shell bridge, all in memory. `present()` = a shell polled within `SHELL_TIMEOUT`, `shell()` = what the GUI may show (None in a browser), `notify(title, body)` queues a notice (dropped without a shell or with setting `desktop_notify` off; called for incoming sync changes), `command(kind, value)` queues a command for the next poll (a newer one of the same kind replaces the older) and wakes a held poll (`poll(wait=)`, `MAX_WAIT`); `report_update()` takes the shell's pushed update state; a state with a lower `rev` than the stored one is dropped (`_take_update()`). Routes `GET /api/desktop` (`{shell, notify}`), `POST /api/desktop/poll` (adds `_desktop_tooltip()`: running jobs, sync state via `_ago()`), `POST /api/desktop/update`, `POST /api/desktop/command` (409 without a shell). GUI: settings panel „Desktop-App“ (`refreshDesktop()` – only with a shell: autostart, notifications, data folder, log; `renderDesktopUpdate()` shows the shell's `update` state with „Update installieren“ / „Nach Updates suchen“, a toast once per announced version; refreshed 20 s after the start (4 s after an update), then every 5 min, every 500 ms while an install runs). Update view: dialog `#update-view` (`startUpdate(request)` for „Update installieren“ and „Zu dieser Version wechseln“, `followUpdate()`, `renderUpdateView()`): steps Vorbereiten › Herunterladen › Prüfen › Installieren › Neustart (the last once the backend is gone), percent, „x von y MB · MB/s · noch etwa …“, German error per `failed_step` (`updateErrorText()`) with the raw text under „Technische Details“, „Erneut versuchen“ / „Protokoll öffnen“; „Im Hintergrund weiter“ leaves the sidebar pill `#update-indicator` (progress ring). localStorage `mtgdeck.update` remembers the install across the restart: the new version shows „Conclave x ist installiert.“, a failed one reopens the view with the error.
- **`http.py`**
  - The single shared `httpx.AsyncClient` for every data source.
  - Rate limits are per host, or per host plus path prefix (Scryfall search, named and collection lookups: 500 ms; everything else: 100 ms).
  - Disk cache keyed by the request, 24 h TTL by default.
  - Always go through `get_json` / `get_text` / `post_json`. Never create another client.
  - Transport errors (no connection, timeout) are retried like 5xx, then raised as `HttpError(0, url, "keine Verbindung"|"Zeitüberschreitung")`. `HttpError.friendly` is the German one-liner naming the service (`service_name()`); the GUI's global `HttpError` handler answers 502 with it.
- **`fmt.py`**: German number format for server texts (`num()` → `3,8` / `1.234,50`, `money()` → `32,00 €`). Import the functions (`de_num`, `fmt_money`), not the module: `gui/app.py` uses `fmt` as a parameter name for formats.
- **Data sources:** `scryfall.py`, `edhrec.py`, `spellbook.py`, `importers.py`, `precons.py`.
  - None of them needs an API key.
  - EDHREC is its public JSON (`json.edhrec.com`), which is unofficial, so parse it defensively. A missing EDHREC page returns 403, not 404.
  - EDHREC page paths are `<commander-slug>[/<theme>][/<bracket-slug>][/budget|expensive]`.
- **`scryfall.compact()`**
  - The canonical card dict used everywhere: the DB, validation and the GUI.
- **`carddb.py`**: a local SQLite DB (`~/.cache/mtgdeck/cards.sqlite`) built from Scryfall bulk data.
  - `MTG_BULK_TYPE` selects the cards file; the default is `all_cards`.
  - The cards file is aggregated to **one row per oracle_id**:
    - the representative printing is chosen by `_printing_score`: English, paper, non-promo;
    - the price is the cheapest paper printing;
    - every printed/face name in every language goes into the `names` table, so German names resolve.
  - `SCHEMA_VERSION` (meta `schema_version`) marks which compact fields exist. v2 adds `layout` / `image_back` for double-faced cards, v3 `tokens` (from `all_parts`: tokens, emblems, markers like The Monarch). An older DB reports `schema_outdated` and `needs_refresh()`; `cards.deck_tokens()` completes missing `tokens` live.
  - Meanwhile `cards._complete_double_faced()` fetches `layout` / `image_back` live for multi-face cards that lack them.
  - The Oracle Tags file (Tagger) goes into `card_tags`. Tags are **rolled up to all ancestors** via `parent_ids`, and aliases live in `tag_aliases`.
- **`cards.resolve()`** is the one entry point for turning names into card data.
  - It tries the local DB first, then falls back to Scryfall `/cards/collection`, then fuzzy `/cards/named`.
  - It returns `renames` (query → English name). Callers must apply these renames to decklists.
  - A name can be a whole card and a face of another one (Rampant Growth is also the prepared spell of „Studious First-Year // Rampant Growth“, layout `prepare`; adventures likewise): `carddb.lookup()` prefers the card of that exact name, then one without faces. `name_choices(name)` (DB `carddb.name_matches()`, else Scryfall `!"name"`) lists every card the name can mean, the whole card first (empty when clear or a full two-part name was typed); `GET /api/card?choices=1` adds it, and the GUI's typed adds (Karten tab „Hinzufügen“/„Vielleicht“, Sammelbestellung, Sammlung) ask via `chooseCard()` → dialog `#card-choice`. Scryfall's `!"name"` also finds such cards, so printings/artwork/German text go through `scryfall.exact_page()` (`same_card()`: the name or its front face); the phone's `scry.german()` filters the same way and `scry.exactFirst()` sorts name searches (Karten tab, iPad builder).
- **`deck.py`**
  - Decklist parsing: plain text, Moxfield/Archidekt exports and `*CMDR*` markers.
  - Role detection: Tagger tags when a card has any (`ROLE_TAGS`), otherwise oracle-text regexes.
  - Stats and text export.
- **`brackets.py`**
  - The official bracket rules table (state: WotC Oct 21 2025 rework plus Feb 9 2026 Game Changer update).
  - `evaluate()` combines three inputs:
    - the Scryfall `game_changer` flag (the Game Changer list is never hardcoded);
    - a mass-land-denial list and regex;
    - Commander Spellbook's `/estimate-bracket` and 2-card combos.
- **`validate.py`**
  - `validate_deck()` orchestrates everything above: 100 cards, singleton, color identity, banned cards, role minimums and the bracket check.
  - It returns a private `_card_data` key that callers must pop before serializing or returning it.
  - A Spellbook outage degrades to a warning and does not fail validation.
- **Import:** `importers.py` turns a link (Archidekt incl. categories, Moxfield v3→v2 best effort, MTGGoldfish/TappedOut/Deckstats text exports, EDHREC average decks) or pasted text into one shape `{source, site, name, commanders, cards: ["N Name"], categories, commander_hint}`; `map_category()` maps site categories to ours. `deckimport.preview()` resolves names, offers `commander_candidates` (legendary cards with `type_line`, `color_identity`, `pairs` = Partner/Background/Friends forever, `fits` = covers the deck's colours alone or with another `pairs` card; fitting ones first) and `suggested` (hint/slug match, else the single fitting card or fitting pair); the GUI shows them in a filterable list (`renderCmdList()`, `pickCommander()`, state `impPick`; „+ Partner“ on pair cards) instead of a `<select>`; `deckimport.save()` validates (bracket `None` = Spellbook/heuristic estimate), fills categories and saves a new deck. Routes `/api/import/preview`, `/api/import`. A blocked Moxfield link (Cloudflare 403, the usual case) switches the GUI to „Liste einfügen“ with a link to the deck (`moxfieldFallback()`); „Aus Zwischenablage einfügen“ (`importFromClipboard()`) reads a copied list (e.g. Moxfield „Copy for MTGA“) and checks it at once. In the desktop app (shell `features` contains `moxfield`) a Moxfield link skips the backend: `openMoxfield()` navigates the main window to the deck, `moxfield.rs` cancels that navigation and opens its own `moxfield` window (the user logs in there; Moxfield refuses API access for deckbuilding apps, their support suggested this), `moxfield.js` (init script) keeps the deck JSON the page itself loads (fetch/XHR to `/decks/all/`) and shows „In Conclave importieren“; its click navigates to `https://conclave-import.invalid/?d=<json>`, which the shell cancels and passes to the main window's `window.conclaveMoxfield()` via `eval` (no IPC for the remote page). Conclave itself never requests Moxfield. `precons.py` reads MTGJSON `DeckList.json` + `decks/<file>.json` (cached, defensive) and imports via `deckimport.save` (`deck["precon"]`). None of these sites was reachable from the dev container; formats follow the public endpoints and are covered by mocks.
- **Beginner helpers:**
  - `glossary.py`: `TERMS` (English term → German name, one-line explanation, kind keyword/action/concept), `find_terms()` for card texts. `cards.card_text(name, lang)` returns per-face Oracle text, the newest printing in `lang` (`printed`) and the terms (route `/api/cards/text`, `/api/glossary`).
  - `health.py`: `check(deck)` → traffic light per area from the stored validation stats (no network); returned by `GET /api/decks/{slug}` as `health`. `deckedit.role_candidates()` + `/role-candidates?role=` fix a role without AI.
  - `rule0.py`: `build(deck)` → Rule-0 rows + copyable text (route `/rule0`).
  - `games.py`: game log in `decks/.games/<slug>.json` (optional `how` from `HOW` = how the game was decided, `started` = `"me"` or an opponent index; both also set by the phone app; `round` = the log of the phone's Runden-Helfer, only from the phone), `stats()`, `learn_focus()`, `ISSUES` quick picks; routes `/api/decks/{slug}/games`. Round logs: `round_turns(round)` = per own turn lost/gained life, commander damage, poison, German event texts and notes; `rounds(items)` = `stats()["rounds"]` over all logged rounds (who dealt the most damage, average life lost per own turn, `worst_turn`, average end life; None without logs); `learn_focus()` (the hint above the Bilanz in the Partien tab) adds answers to the worst source and "früher verteidigen" from it. `summary()` adds `round_turns` to each game with a round; the Partien tab shows them as `roundBoxHtml()` (life sparkline, facts, turn table in `details.round-box`) and the totals as `roundStatsHtml()`.
- **`printorders.py`** (Sammelbestellung): collective print orders in `<proxies>/.orders/<id>.json` with items `{id, kind card|token, name, qty, source, source_slug, type_line, token_id, image}` (equal card+source entries add up). `as_deck()` gives the print pipeline a deck-shaped dict with slug `sammel-<id>` and `print_tokens` (own quantities); `proxy.plan()` plans them via `_plan_tokens()` (MPC TOKEN search, else Scryfall; typed names without image get `_token_image()`). The deck print routes accept order slugs (`_print_deck()`), so plan/prepare/PDF/autofill/add-printed work unchanged. `deck_items()` (all / names / only_missing), `added_since(slug, version)` (cards a rebuild brought in), `card_counts()`. Deck vs. deck: `compare(slug, other)` → `added` (`owned`, `missing` capped by `collection.missing_counts`, `basic`, `commander`) / `removed` / `common` / `totals`; `compare_candidates(slug)` (the `copied_from` deck first, then by shared cards); `compare_items()` order positions (`OrderAdd.compare_with`). `to_moxfield(order)` → (text, tokens left out); route `GET /api/orders/{id}/export[?download=1]` (header `X-Tokens-Left-Out`). Routes `/api/decks/{slug}/compare?other=` (adds images/prices; without `other` the best match), `/api/orders[/{id}[/items[/{item}]]]` (add: items, deck+names/only_missing/since_version, text, url), `/api/decks/{slug}/added?since=`, `/api/tokens/search`.
- **`maybe.py`** (Vielleicht-Liste): `deck["maybe"]` = `[{name, category}]`, a content key (versions and syncs; `merge.merge_deck` merges it per card name like `cards`), but nothing counts it (card count, validation, bracket, price, print, export). A card is in the deck or on the list, never both: `change()` (shared by `deckedit` and `appops`, no imports) drops list entries that are in the deck, `maybe_add` moves deck cards there („X → Vielleicht“), `maybe_remove` takes names off. Desktop: last group „Vielleicht“ in the card list (`maybeHtml()`, edit state `edit.maybeAdd`/`maybeRemove`, `addMaybe()`/`removeMaybe()`, row button per card, „Vielleicht“ next to „Hinzufügen“); a drag from Scryfall onto the right half of the window (`dropOnMaybe()`, second box `#drop-maybe`) puts the card on the list. iPad builder: „?“ on every tile, „Vielleicht“ in the card sheet, „Auf die Vielleicht-Liste“ in the deck card sheet, list at the end of the deck pane; draft `maybe: {name: {on, category}}`; `deck.edit` takes `maybe_add`/`maybe_remove`. The phone's deck screen shows the list read-only.
- **`deckedit.py`**: `edit_deck()` changes a saved deck directly (add/remove/set_qty/set_category, plus `maybe_add`/`maybe_remove`), re-validates via `revalidate()` and saves one version with a "Manuell: …" note (route `POST /api/decks/{slug}/cards`). `similar_cards()` suggests replacements (local DB tags, else Scryfall `otag:` search).
- **`collection.py`**: the user's collection in `collection.json` (`MTG_COLLECTION_FILE`, gitignored).
  - One entry per printing and place: name, qty, proxy, foil, lang, `set`/`set_name`/`collector_number`/`scryfall_id`/`image` (artwork), price at import, note, „Ort“ = `place` (free text ≤ `PLACE_MAX`) or `place_deck` (a deck slug; then the text is ignored for merging). Identical entries are merged (`_key`, mirrored by `appops._coll_key` and the phone's `collKey`). `add(place=, place_deck=)`, `update(place=)`, `bulk_update(ids, place=, place_deck=, proxy=, foil=, lang=, delete=, qty=)` (mass edit, route `POST /api/collection/bulk`; `qty` = only that many copies of each entry, split off into an entry of their own: the Ort dialog's „Wie viele davon?“ for one entry with several copies, and `askCount()` for its Proxy/Foil boxes or „Ändern …“), `places()` (in `GET /api/collection`). Desktop: Ort column button per row, row checkboxes + sticky `#coll-bulk` bar: „Ort setzen …“ → `#place-dialog`, `#coll-bulk-set` „Ändern …“ (Original/Proxy, Foil, Sprache), „Löschen“ (asks first), `#coll-place` filter, Ort field in the add dialog prefilled with the last one (`store` `collplace`).
  - `parse_import()` reads ManaBox/Moxfield/Archidekt CSV (column aliases in `_COLS`) and plain lists. Printings resolve via `scryfall.by_identifiers()` (id or set+number); a picked printing (`printing` dict) is stored as is.
  - `deck_ownership()` (real/proxy/missing, `places` = where the copies are per Ort and proxy – the tooltip of the ✓/P badge in the deck list (`ownershipBadge()`), shopping list, `shared_shortages` across decks; basics count as owned), `missing_counts()` for printing only missing cards, `add_printed()` after printing, `search_owned()` for building from the collection.
  - Copies placed in a deck (`place_deck` = its slug) are the deck's own cards: `deck_ownership()` returns them per card as `copies` (real before proxy, at most as many as the deck needs; printing, foil, image (derived from `scryfall_id` when missing), today's price of that printing via `scryfall.by_identifiers()`, foil price for foils, else the stored one) and `value` = `{total, cheapest, own, foil, proxy, rest}` (real placed copies at their own price, placed proxies 0, the rest at the cheapest printing like `price_total`). Desktop: the card list and grid show that printing (`shownCopy()`, `deckCopies()`), a „Foil“ tag and an animated holo sheen (`.foil-sheen`, off with reduced motion), the head says „Wert …“ instead of the price (`deckValue()`, tooltip `deckValueTip()`; the budget check keeps `price_total`). The big card view (`renderCardViewFaces()`) is a 3D card (`.card3d`: front + Magic card back `CARD_BACK`; leans towards the mouse, drag turns it and it settles on the nearer side, double click or „Umdrehen“ `#card-view-flip` turns it over; sheen and glare follow the angle) with „Liegt im Deck: …“ chips per own copy (`#card-view-copies`). Phone and iPad do not show own copies yet.
  - Moving copies into a deck: the deck list's ✓/P badge is a button (`ownershipBadge(…, button)`, `data-act="own"`, larger invisible hit area) that opens dialog `#own-copies` (`openOwnCopies()`, `renderOwnCopies()`, filter Alle/Echt/Proxy in `store` `ownfilter`): `card_copies(name, slug)` = the card's entries `here` (Ort = this deck) and `elsewhere` (`used_by` = the deck it lies in when that deck plays the card), „Ins Deck“ = `move_to_deck(entry_id, slug, qty)` (splits multi-copy entries like `bulk_update(qty=)`; an equal entry already in the deck keeps its id) → `{id, qty, place, place_deck}`; undo („Zurücklegen“ in the dialog, „Rückgängig“ in the toast) sends that back through `POST /api/collection/bulk`.     - Use the design tokens in `style.css` (`--space-*`, `--fs-*`, `--radius*`, semantic colours incl. `--input-border` ≥ 3:1) for light and dark. Surfaces are `.panel`; `.card` is reserved for card rows (hover preview uses `.card[data-img]`).
    - Show and hide with the `hidden` attribute. Report with `toast(text, kind, ms, {label, run})` (optional action button, e.g. „Rückgängig“) and ask with `ask()` (a `<dialog>`), never `alert`/`prompt`/`confirm`. Keep one primary button per view and put rare options into `<details class="more">` or the ⋯ menu.
  - `POST /api/decks/new` creates an empty deck with its commander(s) (GUI: import sub-mode `manual` „Selbst zusammenstellen“, then edit mode). Drag & drop from scryfall.com: `dropcards.py` turns a browser drag (`text/uri-list` › `text/html` hrefs, else image srcs or `alt` › `text/plain` links or name lines) into Scryfall identifiers (`from_url()`: card page `/card/<set>/<number>`, API `/cards/<id>|<set>/<number>`, image CDN uuid) and `resolve()` → names; route `POST /api/cards/drop`. GUI: document-level `dragover`/`drop` (`isCardDrag()`: not a drag started in the app, not image files for the open artwork picker; every outside drop is caught so the browser never navigates to the link), overlay `#drop-overlay`; in an open deck `dropCardsIntoDeck()` (Karten tab, edit mode, `addCard()`, toast with „Rückgängig“), elsewhere `dropCommander()` fills „Selbst zusammenstellen“ (second drop = partner). The desktop window sets `dragDropEnabled: false`, otherwise Tauri swallows the drop and the page never sees it.
  - Every job (print, MPC Autofill, card DB) runs through `_register()`: whatever happens (crash in a `finish` callback, cancel), `Job.close()` emits a final `done` (ok false if none was sent) and sets `done`, so streams never hang. Errors go out via `_error_text()` (friendly for `HttpError`, plain for store/lookup/value errors, type + message for bugs). Finished jobs are pruned after `JOB_KEEP_SECONDS`.
  - Events stream to the browser over SSE, with `Last-Event-ID` resume.
  - Background jobs via `_start_runner(runner)`. They emit `progress` / `print` / `console` events besides text.
  - Print routes: `/api/decks/{slug}/print/{plan,alternatives,choose,prepare,pdf,autofill,files,files/{xml|pdf}}`. Settings: `/api/settings`.
  - Version routes: `/api/decks/{slug}/versions[/{v}[/restore]]`, `/diff?a=&b=` and `/copy`.

## Tests

- Tests must never hit the network.
- The mock also fakes a token search (`t:token` queries → two Treasure tokens). Route tests with background jobs use `with TestClient(app) as client:` so the event loop survives between requests.
- The mock also fakes MTGJSON (`GraveTroupe_C99`), Archidekt deck 4242, Moxfield (v3 blocked, v2 answers; `blocked` ids fail), MTGGoldfish 777, TappedOut, Deckstats, the EDHREC average deck for Meren and German printings (`GERMAN`, `lang:de` searches).
- `tests/conftest.py` sets up an autouse fixture that:
  - replaces `http._client` with an `httpx.MockTransport` that fakes Scryfall, EDHREC and Spellbook;
  - redirects the cache, DB, decks, blacklist, table rules, backups, collection and proxies to `tmp_path`, and sets `MTG_SYNC_DIR` / `MTG_SYNC_DATA` there;
  - disables throttling.
- Backend as a program: `test_launch.py` (paths under `MTG_HOME`/frozen, launcher arguments, token guard, health; `MTG_TEST_SUBPROCESS=1` also starts a real server on a free port). Desktop bridge: `test_desktop.py` (poll/notices/commands/tooltip).
- Phone app: `test_phone_app.py` (read model, served files and CSP, `appops` linking/idempotency/errors, the full route round trip phone → server → PC `SyncClient`, redirects and the versioned `sw.js`, and that importing `sync.server` pulls in no httpx/PIL). The UI itself is checked with Playwright scripts outside the repo (iPhone and Pixel emulation, demo flows, tap counts, tap targets ≥ 44 px, light/dark; paired against a real server: pairing by code/link/iPhone steps/fake-camera QR, offline queue, offline start, undo after sending, sign-off, revoked).
- Sync tests: `test_sync.py` runs two `Roots.under()` devices against a `SyncStore` via `LocalTransport`; `test_sync_server.py` runs the real server app in a `TestClient` and passes it as `client=` to `HttpTransport`/`service` (GUI route tests patch `service.HttpTransport` the same way and set `MTG_SYNC_AUTO=0`).
- Any card name starting with `Filler` is synthesized on demand. `deck_lines()` builds a legal 99-card main deck for Meren (BG).
- `CARDS` includes two opponent commanders (Atraxa, Praetors' Voice; Krenko, Mob Boss).
- `PRINTINGS` fakes specific printings for `/cards/collection` id and set+number lookups; "Pitiless Plunderer" carries `all_parts` (Treasure token, The Monarch) for token tests; `otag:`/`t:` searches return replacement candidates.
- Add new endpoints to the mock `handler`. It also fakes `cards.scryfall.io`, the MPC Autofill server (`MPC_SERVER`) and its CDN, returning generated images.
- `test_proxy.py` drives the terminal with a fake `autofill.py` that shows the same InquirerPy menu (inquirerpy is a dev dependency). The test answers it with raw arrow-key input.
